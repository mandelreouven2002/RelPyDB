6. Concepts

The relational vocabulary RelPyDB uses — tables, rows, keys, and queries — and how each one maps onto a Python object.

What is RelPyDB?

RelPyDB is an in-memory relational object library. It lets Python code define tables, constraints and queries without running a database server. "Relational" means data is organized into named tables of rows that share the same columns, and tables can reference each other through keys — the same model SQL databases use, just expressed as Python method calls instead of SQL text.

Core terminology

These terms recur throughout the documentation and mean the same thing they do in any relational database:

TermMeaning
SchemaThe set of table and column definitions — names, types, and constraints — without any data in them yet.
Primary keyThe column (or columns) that uniquely identifies a row in its table. RelPyDB rejects a second row with the same primary key value.
Foreign keyA column whose value must match a primary key value in another table, used to express "this row belongs to that row" relationships and to drive automatic joins.
ConstraintA rule RelPyDB enforces automatically: nullable=False, a primary key, a foreign key, or a unique index.
QueryA chain of method calls — where(), select(), join(), order_by() — that describes which rows to return, without changing any stored data until you call a terminal method like to_list().
ViewA named query, saved so it can be re-run with one call instead of being rewritten each time.

Putting it together

A schema definition, some rows, and a query, all in one script:

from relpy import RelPy, AutoNumber, col

db = RelPy()
db.create_table("users")
db.add_column("users", "id", AutoNumber, is_primary_key=True)
db.add_column("users", "name", str, nullable=False)

db.insert("users", {"name": "Alice"})
db.insert("users", {"name": "Bob"})

result = db.query("users").where(col("name") == "Alice").to_list()
Output
[{"id": 1, "name": "Alice"}]

The next chapter, 7. Tables and Schema, covers create_table and add_column in full, including every constraint they support.

When to use it

  • Learning relational modeling in Python.
  • Building small in-memory relational objects.
  • Testing domain logic without setting up SQL.
  • Exporting data to JSON, pandas, NumPy or SQL insert scripts.
  • Keeping small local data objects with optional encrypted columns.

When not to use it

RelPyDB is not PostgreSQL, SQLite or DuckDB. It is not designed for concurrent multi-user workloads, large production datasets or transactional database guarantees.
