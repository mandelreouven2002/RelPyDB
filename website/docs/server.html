18. Server and Remote Client

Serve any RelPyDB database over HTTP and connect to it from other processes or machines with the identical RelPyDB API.

Mental model

A RelPyDB server holds the durable data (optionally SQL-backed). Each client is itself a RelPyDB database with a full local mirror synced from the server. Queries — including joins, group_by and lambda filters — run locally on the mirror, so they behave identically to any other RelPyDB database, while every change is pushed to the server, which persists it.

Django-style. Think of python -m relpy.server as a small runserver for your database, and RelPy.connect("remote", ...) as a client that speaks the normal RelPyDB API to it.

Run a server

Define a database in Python and serve it. The backend can be in-memory or any SQL database from the Databases page.

server.py
from relpy import RelPy, AutoNumber

db = RelPy(backend="sqlite", path="app.db")
db.create_table("users")
db.add_column("users", "id", AutoNumber, is_primary_key=True)
db.add_column("users", "name", str)

db.serve(host="0.0.0.0", port=8000)          # blocking

Or run it from the command line:

shell
python -m relpy.server --backend sqlite --path app.db --host 0.0.0.0 --port 8000

The CLI accepts:

FlagMeaning
--backendmemory (default), sqlite, postgres, mysql, oracle, azure, aws.
--pathFile path for the sqlite backend.
--urlSQLAlchemy URL for the other SQL backends.
--host / --portInterface and port to bind (default 127.0.0.1:8000).
--tokenOptional bearer token required from clients.
--verboseLog every request.

For notebooks, tests, or running a server alongside other code, start it in a background thread:

background.py
from relpy import RelPyServer

server = RelPyServer(db, port=8000, token="secret").start_in_thread()
# ... do work ...
server.stop()

Connect a client

A client uses the same RelPyDB API against the live server. Because it keeps a local mirror, call reload() to pull fresh state if other clients may have changed the server.

client.py
from relpy import RelPy, col

remote = RelPy.connect("remote", url="http://localhost:8000", token="secret")

remote.insert("users", {"name": "Ada"})
remote.query("users").where(col("name") == "Ada").to_list()

remote.reload()   # re-pull server state into the local mirror

Joins and grouping work exactly as they do locally, because they run on the client's mirror:

client_query.py
remote.query("orders").join("users").group_by("users.name").aggregate(
    total=sum_("orders.amount"), n=count()
).to_list()

Authentication

Pass token= to the server to require a bearer token. Clients must present the same token, or the connection is rejected with a RemoteError.

auth.py
RelPyServer(db, port=8000, token="s3cret").start_in_thread()

RelPy.connect("remote", url="http://localhost:8000", token="s3cret")  # ok
RelPy.connect("remote", url="http://localhost:8000", token="wrong")   # RemoteError

Mounting in an existing web stack (WSGI)

make_wsgi_app returns a standard WSGI application you can mount behind gunicorn/uWSGI or alongside a Django deployment.

wsgi.py
from relpy import RelPy, make_wsgi_app

db = RelPy(backend="postgres", url="postgresql+psycopg://...")
application = make_wsgi_app(db, token="secret")   # WSGI callable

The server exposes POST /rpc (the RelPyDB protocol) and GET /health.

What travels over the wire

The protocol is deliberately small: a single POST /rpc endpoint that carries an operation and its arguments, plus a GET /health check. Values are type-preserved across the wire (dates, bytes and JSON survive the trip). Query logic never travels as SQL — joins, grouping and lambda filters run on the client mirror, so remote semantics match local semantics exactly.

Error handling

Remote problems surface as clear, catchable exceptions (all under RelPyError). See Common Errors and Limitations for the full connectivity table.

errors.py
from relpy import RelPy, BackendConnectionError, RemoteError

try:
    remote = RelPy.connect("remote", url="http://localhost:8000", token="secret")
except BackendConnectionError as exc:
    print("Server unreachable:", exc)
except RemoteError as exc:
    print("Server rejected the request (e.g. bad token):", exc)

When to use which

You want…Use
Fastest, ephemeral, no setupRelPy() (in-memory)
Durability on one machineRelPy(backend="sqlite", path=...) or another SQL backend
Multiple processes / machines sharing one databaseA RelPyServer + RelPy.connect("remote", ...) clients
